# 布仕曼洗护 · 户外装备洗护微信小程序（源码）

服务冲锋衣、羽绒服、帐篷、登山鞋等装备的**清洗、修复、防水保养**预约下单，
包含服务列表、预约下单、订单跟踪、装备档案、养护知识、会员次卡等模块。

> 本次交付同步包含 **H5 版**（`布仕曼洗护-H5版.html`，双击即可在手机/电脑浏览器打开，
> 数据存本机，无需服务器），与小程序版页面/业务流/视觉规范完全一致，可先行用于验收演示。

## 〇、视觉与图标规范（v2.0）

- **设计系统集中在 `app.wxss`**：色阶 / 字阶 / 间距 / 圆角 / 阴影 / 组件类全部收敛为令牌，
  页面样式只允许引用令牌与组件类，不写裸色值。规则与理由见 `docs/05-视觉改版说明.md`
- **全部页内图标为内联 SVG**：`utils/icons.js`（39 个图标，24 网格 / 1.7 描边 / 圆角端点），
  颜色已烘焙，供 `<image>` 直接使用
- **图标可维护**：SVG 源码在 `tools/icons/build.js`，改完重跑即可再生成
  `utils/icons.js` 与 `images/tab-*.png`
- **tabBar 图标**：微信限制 tabBar 仅支持 png/jpg，由同一套几何渲染为
  `images/tab-*.png`（81×81 透明底，inactive 灰 / active 品牌绿）
- **质感来自 CSS 纹理**：`tex-bead / tex-stitch / tex-rain / tex-grid` 用渐变绘制面料质感，
  零图片资源、任意分辨率锐利

## 一、快速运行（演示模式）

1. 打开微信开发者工具 → 导入项目 → 选择本目录
2. `project.config.json` 中 `appid` 替换为你自己的小程序 AppID（测试可先用"测试号"）
3. 编译运行 —— 默认 `USE_MOCK = true`，全部数据来自本地模拟（`utils/mock.js`），
   无需后端即可体验完整下单-支付（模拟）-订单跟踪-装备档案流程

## 二、上线前必须完成的配置（与《案例分析报告》第6章对应）

| 步骤 | 事项 | 参考耗时 |
| --- | --- | --- |
| 1 | 注册小程序（企业/个体户主体，个人主体不可交易） | 1 天内 |
| 2 | 微信认证（300 元/次，个体户部分场景 30 元） | 1-5 个工作日 |
| 3 | 开通微信支付商户号（普通商户 48 小时内审核） | 与上并行 |
| 4 | **小程序 ICP 备案**（平台初审 1-2 日 + 管局 1-20 个工作日，不可加急） | 2-4 周 |
| 5 | 服务类目申请（生活服务类，需与营业执照经营范围匹配） | 提审前完成 |
| 6 | 配置用户隐私保护指引（收集手机号/地址必须声明） | 提审前完成 |

> 提示：备案与开发并行启动，否则会出现"代码写完却无法提审"的空等。

## 三、支付对接（两条路线）

### 路线 A（主路线）：自建订单 + 微信支付 JSAPI
1. 后端实现 `POST /pay/createOrder`：调用微信支付 V3 统一下单，返回
   `timeStamp / nonceStr / package / signType / paySign`
2. 打开 `utils/pay.js`，将 `USE_MOCK` 关闭后按 TODO 注释接入
3. 支付回调中更新订单状态（后端负责，注意验签与幂等）

### 路线 B（补充货架）：微信小店
微信小店面向**实物电商**，洗护服务类商品存在类目限制（生活服务类目需
营业执照对应经营范围及从业人员健康证等资质）。建议仅将洗护剂、防水喷雾、
礼品卡等**实物/标准化券类**上架微信小店，服务履约仍由本小程序承载。

## 四、目录结构

```
├── app.js / app.json / app.wxss      全局
├── config/index.js                   品牌与接口配置（USE_MOCK 开关）
├── utils/                            请求封装 / 模拟数据 / 支付封装 / icons.js（SVG 图标库）
├── images/                           tabBar 图标（由同一套 SVG 几何渲染）
└── pages/
    ├── index            首页（分类入口 + 活动位 + 知识精选）
    ├── services         服务列表（清洗/修复/保养）
    ├── service-detail   服务详情与规格选择
    ├── booking          预约下单（到店/寄洗、时间、地址、装备关联）
    ├── order-list       订单列表
    ├── order-detail     订单详情（进度时间线 + 洗前洗后照片）
    ├── gear             装备档案
    ├── gear-edit        装备新增/编辑（含养护记录）
    ├── articles         养护知识列表
    ├── article-detail   知识详情（文末服务入口）
    ├── membership       会员次卡（服务套餐，合规设计）
    └── profile          我的
```

渲染快照与设计审查工具在仓库根目录 `tools/` 下，不参与小程序打包：

```bash
npm run preview   # 用真实页面代码渲染 12 页截图到 previews/
npm run audit     # 设计令牌 / 对比度 / 字号 / 图片尺寸 / 绑定残值审查
```

## 五、接后端时需要做的

- `config/index.js`：`USE_MOCK = false`，`BASE_URL` 换成你的域名（需 HTTPS + ICP 备案）
- 推荐后端集合：`services / orders / gears / users / packages`
- 订单状态机与 `utils/mock.js` 中保持一致：
  `待支付 → 已接单 → 清洗中 → 质检中 → 配送/待取 → 已完成`
- 消息触达：装备档案到期提醒使用**订阅消息**（`wx.requestSubscribeMessage`），
  模板需在小程序后台申请

## 六、合规要点（详见报告 6.6 节）

- 不得以储值卡形式预售，次卡按"服务套餐商品"设计（限本人、明有效期、可退款规则）
- 首页或关于页需展示备案号；赔付与保价规则建议写入下单页
